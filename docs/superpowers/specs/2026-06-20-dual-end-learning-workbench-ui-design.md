# 双端学习工作台 UI 与操作闭环设计

日期：2026-06-20

## 目标

把数学分析学习工作台从“网页端已成型、小程序端可用但少图示”推进为双端一致的学习产品。用户在网页和小程序里都应理解同一条学习闭环：继续学习、进入知识点、阅读讲义与图示、完成练习、向 AI 追问或提交批改、回到进度反馈。

## 设计原则

- 保留现有编辑/教科书视觉语言：暖纸底、墨黑正文、酒红强调、金色辅助、克制边框和衬线排版。
- 不做营销页，不新增账号、后台编辑器或付费系统。
- 图示是教学材料，不是装饰。网页端继续用程序化 SVG；小程序端先做可用的图示卡与轻量示意渲染，再逐步补全复杂图形。
- 双端入口命名保持一致：讲义、教学图示、思考题、易错提醒、练习、AI 老师、评分要点。
- 进度状态必须出现在学习路径上，而不是只藏在练习反馈里。

## 网页端体验

网页端保留三栏工作台结构。

左栏从章节列表强化为学习路线：章节状态、样板完成、草稿、待整理、掌握状态和题量都以更可扫的方式展示。中栏强化当前知识点头部，讲义、学习目标、教学图示、思考题、易错提醒形成稳定阅读顺序。练习区保持题目列表与当前题工作区分离，批改结果、提示和评分要点作为复盘材料呈现。右栏 AI 老师减少设置对话的干扰，突出它正在围绕当前知识点工作。

## 小程序端体验

首页继续以继续学习和章节目录为主，但章节列表要更明确展示学习进度。章节页中的知识点列表显示题量、最高分和是否有图示。学习页保持讲义/练习双 tab，讲义 tab 内加入教学图示区块，并在顶部显示当前位置、题量、最高分和图示数量。练习 tab 保持筛选、作答、提示、批改、评分要点和问 AI 老师的完整路径。

## 小程序图示策略

第一阶段交付可用图示链路：

- `scripts/build-wx-data.js` 从章节的 `diagramFile` 读取图示 JSON。
- 每个知识点根据 `diagramIds` 与 `knowledgePointIds` 匹配图示。
- 小程序学习页渲染 `diagram-card` 组件，显示图题、类型、说明、学生提问与教学提示。
- 对数轴、序列、函数曲线、ε-δ、渐近线、跳跃、表格等高频类型给出轻量示意，不阻塞学习主流程。

第二阶段再追求像素级一致：把网页图形引擎的坐标映射、曲线采样和表格渲染进一步移植到小程序 Canvas 或 SVG 图片方案。

## 发布叙事

GitHub PR 应讲清三件事：

1. 这是一个双端学习闭环升级，不只是样式调整。
2. 网页端已经具备程序化数学图示、自托管字体和 AI 辅导，小程序端补齐图示入口后更接近完整学习端。
3. 内容与代码仍解耦，JSON 源继续作为双端共享内容源。

## 验收标准

- 网页端构建通过，三栏工作台在宽屏和窄屏都不出现明显重叠。
- 小程序数据生成脚本能把图示打包进知识点。
- 小程序学习页能显示至少数列极限、函数极限章节的教学图示卡。
- `npm run validate:wx-diagrams` 能验证图示数据与组件接入。
- PR 描述覆盖功能价值、用户影响、验证命令和已知边界。
