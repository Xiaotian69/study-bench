# AI 数学分析同步学习助手设计

日期：2026-06-01

## 1. 项目定位

本项目先做一个面向自用和小范围内测的 Web 学习工作台，核心方向是“AI 同步课老师”，不是通用 PDF 问答工具。

第一版课程聚焦《数学分析》上册。开发者维护教材结构、知识点、例题、课后题和教学脚本，用户只选择已经整理好的课程学习，不上传自己的教材 PDF。AI 负责讲解、追问、提示、批改和学习反馈，但不负责自由决定整门课怎么教。

长期目标是形成一个可扩展的学习产品：先支持日常教材精读，未来加入薄弱点诊断、期末冲刺、错题本、掌握度图谱和课程后台。

## 2. 第一版目标

第一轮目标是完成：

- 数学分析上册目录框架。
- “数列极限”作为深度样板章节。
- 按教材小节推进，内部拆成知识点。
- 每个知识点包含短讲、追问、例题、练习、反馈和掌握度记录。
- 题目以教材例题和课后题为主，AI 不凭空生成正式题。
- 用户可选择模型并填写自己的 API Key。
- UI 做成美观、清爽、适合长时间学习的 Web 学习工作台。
- 可部署为内测预览链接，方便非开发者朋友打开体验。

不在第一版范围内：

- 正式账号系统。
- 正式付费系统。
- 多课程后台编辑器。
- 用户自行上传教材。
- 完整商业化合规流程。

## 3. 产品形态

第一版使用 Web 应用形态。首页不是营销页，而是直接进入学习工作台。

主要界面由三部分组成：

- 左侧：课程目录、章节进度、当前所在小节。
- 中间：当前知识点讲义、公式、图示、例题和题目。
- 右侧或下方：AI 老师对话、提示、批改和学习反馈。

用户体验应像跟着老师同步学习课本：

1. 选择《数学分析》课程。
2. 进入上册目录。
3. 进入“数列极限”样板章节。
4. 按知识点完成短讲、追问、练习和反馈。
5. 系统记录掌握状态，并建议继续、复习或补练。

## 4. 学习流程

每个知识点采用固定学习闭环：

1. 预备问题：AI 用一个短问题检查用户已有理解。
2. 短讲：展示开发者整理的核心讲义，AI 可补充口语化解释。
3. 定义/定理精读：对关键数学语言逐句拆解。
4. 关键追问：AI 追问定义条件、证明逻辑和常见误区。
5. 例题拆解：选用教材例题，展示或引导关键步骤。
6. 基础练习：检查定义、定理和直接应用。
7. 提升练习：训练证明、推导、反例和综合题。
8. 反馈与补讲：AI 根据学生答案指出漏洞，分层提示。
9. 掌握度记录：记录未学、初步掌握、熟练或薄弱。
10. 路径调整：通过则进入下一知识点，薄弱则安排补题或复讲。

## 5. 课程内容结构

第一版课程内容先用结构化文件维护，后续可迁移到后台编辑器。

课程层级：

```text
课程
  册
    章
      小节
        知识点
          教学步骤
          例题
          练习题
          图示
```

知识点建议字段：

- 学习目标。
- 核心讲义。
- 教材依据。
- 关键定义。
- 关键定理。
- 证明思路。
- AI 追问。
- 常见误区。
- 例题列表。
- 练习题列表。
- 掌握度规则。
- 关联图示。

题目建议字段：

- 来源：教材例题、课后习题、改编题或自编过渡题。
- 所属章节、小节和知识点。
- 难度：基础、中档、提升。
- 类型：定义理解、计算、证明、反例、综合。
- 推荐时机：讲后立刻练、复盘、章节测验、冲刺。
- 标准解法或评分要点。
- 分层提示。
- 常见错误。

## 6. 题库策略

第一版不让 AI 动态生成正式题目。题目主要来自教材例题和课后习题，由开发者整理、标注和分级。

AI 可以做：

- 从已标注题库中选择当前最合适的题。
- 根据用户答案给提示和批改。
- 对教材题进行追问。
- 基于原题做少量变式提问。
- 判断是否需要补练基础题。

AI 不应做：

- 临时编造整套正式题库。
- 跳过课程脚本自由安排教学。
- 在没有教材依据时给出不确定的证明训练。

## 7. 教学图示

数学分析学习需要图示辅助，尤其是数列极限、epsilon 邻域、函数极限、连续性、上下确界和区间套等内容。

第一版应支持“课程图示”作为内容的一部分。图示不是装饰，而是教学步骤中的材料。

数列极限样板章节优先准备：

- 数轴上的 epsilon 邻域。
- 数列项逐渐落入邻域的示意图。
- “从某一项 N 之后全部满足条件”的图。
- 收敛与不收敛数列的对比图。
- 有界数列示意图。
- 单调有界数列趋近极限的示意图。

实现建议：

- 数学精确图优先使用程序化 SVG、Canvas 或图表组件生成。
- 每张图保留可编辑的源定义，例如坐标点、区间、标注和公式。
- 图示与知识点绑定，进入对应教学步骤时展示。
- AI 可以解释图，但不应随机生成数学图，以免出现错误。
- 后续可做一个简单绘图脚本或图示组件库，开发者在课程文件中引用图示 ID。

## 8. AI 工作方式

用户看到的是一个 AI 老师，底层按任务拆成固定能力：

- 讲解助手：根据当前讲义补充口语化解释。
- 提问助手：按预设追问检查理解。
- 批改助手：判断答案的概念、推理、条件和证明语言。
- 提示助手：按层级给提示，最后才给完整思路。
- 学习记录助手：根据表现建议掌握度变化。

AI 的上下文应限制在：

- 当前课程。
- 当前章节、小节和知识点。
- 当前教学步骤。
- 当前题目的评分要点、提示和常见错误。
- 用户最近回答和历史掌握情况。

模型与 API Key：

- 用户在设置页选择模型供应商和模型。
- 用户填写自己的 API Key。
- 第一版 API Key 优先保存在浏览器本地，不进入数据库。
- 初期支持一到两个供应商即可，后续再扩展。

## 9. UI 方向

UI 应是美观、清爽、适合学习的工作台，而不是粗糙后台或普通聊天页。

设计气质：

- 安静、清晰、学术、温和。
- 类似精美讲义和一对一辅导窗口的结合。
- 公式排版漂亮，必须支持 LaTeX。
- 题目、提示、答案、反馈层次明确。
- 颜色克制，不做幼稚风，也不做营销页风格。
- 第一版以电脑和平板体验为主，移动端保证基本可用。

关键界面：

- 课程目录页。
- 章节学习页。
- 当前知识点学习区。
- AI 老师互动区。
- 练习与批改区。
- 模型和 API Key 设置页。
- 简单学习进度与掌握状态。

## 11. 阶段计划

阶段 0：项目准备

- 初始化 GitHub 仓库。
- 创建 Next.js 项目。
- 跑通本地开发。
- 建立基础 UI 壳子。

验收标准：两位开发者都能本地运行网页。

阶段 1：课程样板

- 建数学分析上册目录。
- 深度整理“数列极限”。
- 拆知识点和教学步骤。
- 录入例题、习题、难度和提示。
- 准备必要教学图示。
- 支持 LaTeX 公式显示。

验收标准：不用 AI，也能按页面完整学习数列极限的结构化内容。

阶段 2：AI 同步老师

- 接入模型设置和 API Key。
- AI 按当前知识点短讲。
- AI 追问和批改。
- AI 分层提示。
- 记录掌握度建议。

验收标准：用户可以完成一次“讲、问、练、批改、反馈”的闭环。

阶段 3：内测预览

- 部署测试网页。
- 设置简单访问方式。
- 邀请朋友体验。
- 收集 UI、流程、题目难度和 AI 反馈质量。

验收标准：非开发者打开链接即可完成一个小节学习。

阶段 4：扩展和产品化

- 补更多章节。
- 做错题本。
- 做掌握度图谱。
- 做期末冲刺模式。
- 做后台编辑器。
- 做账号、权限、付费和合规。

## 12. 关键风险

内容工作量风险：

数列极限样板要做深，不应一开始追求整本书全部深度覆盖。采用“上册目录框架 + 样板章节深做 + 按模板扩展”的策略。

AI 质量风险：

AI 不能自由发挥教学结构。通过课程脚本、题目标签、评分要点和分层提示限制 AI 范围。

版权和内容风险：

原始教材 PDF 不提交到仓库，不在前台公开，不作为可下载内容分发。用户看到的是整理后的课程结构、讲义、题目训练和学习流程。正式商业化前需要进一步审查教材引用、题目改编和版权边界。

新手开发风险：

第一版避免后台编辑器、账号系统和正式付费系统。先验证学习闭环，再逐步产品化。

## 13. 当前决策

- 第一版做 Web，不做小程序或 App。
- 选择“本地开发 + 云端预览部署”的路线。
- 用户不上传教材，课程由开发者维护。
- 课程内容先用文件维护，后续迁移后台。
- 学习模式选择混合型：短讲、追问、练习、反馈。
- 第一版深度样板章节选择“数列极限”。
- 题目来自教材例题和课后习题，AI 不生成正式题。
- UI 要做成美观的学习工作台。
- 教学图示作为课程内容的一等对象。
