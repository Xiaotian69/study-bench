# AI 老师风险列表与规避建议

日期：2026-06-02
对应任务包：9（QA 验收清单与风险列表）

本列表汇总 AI 老师在下一阶段最可能出问题的点，每条给出**现象**、**影响**和**具体规避建议**（含已实现的防线与待补的防线）。

---

## R1. 模型输出 JSON 解析失败
- 现象：grade/ask/hint/mastery 任务要求严格 JSON，但模型返回了带 Markdown 围栏、解释文字或截断的内容。
- 影响：前端拿不到结构化结果，批改/提示流程中断。
- 规避：
  - 已实现：`lib/ai/tutorRuntime.ts` 的 `stripJsonFence` 去围栏 + `parseTutorModelOutput` 容错解析；解析失败回退到 `buildTutorFallbackResponse`。
  - 已实现：JSON 任务温度设为 0.2。
  - 待补：解析失败时先**重试一次**并追加“只输出 JSON 对象”的指令（见 `docs/ai/tutor-runtime-contract.md` 第 4 节），再降级。
  - 验收：用故意不返回 JSON 的 mock 验证降级路径不抛错。

## R2. 模型脱离当前知识点自由发挥
- 现象：模型扩展到其他章节、补充超纲内容，或自行改变教学顺序。
- 影响：偏离课程脚本，违反“AI 不自由决定怎么教”的产品定位。
- 规避：
  - 已实现：系统提示限定“只围绕当前知识点和当前题目”，并只注入裁剪后的知识点/题目。
  - 待补：发送前按任务裁剪上下文字段（ask 不传 rubric、grade 不传 socraticQuestions），减少越界材料。
  - 验收：抽查若干 explain/ask 输出，确认未引入注入数据之外的定理或题目。

## R3. 模型提前泄露答案
- 现象：学生只点到第 1 级提示，模型却给出完整解题过程；或批改反馈里直接写出标准答案。
- 影响：破坏“分层提示、最后才给完整思路”的教学设计。
- 规避：
  - 已实现：系统提示“除最后一级提示外不得直接给完整答案”；hint 任务 `isFinalAnswerRevealed` 仅在 `level==maxLevel` 为 true。
  - 已实现：hint 降级直接取课程数据 `hints[level-1]`，天然不越级。
  - 待补：对模型返回的 hint 文本做“是否疑似泄露最终答案”的轻量校验（如长度/关键结论匹配），异常时回退到题库提示。
  - 验收：在非最后层级请求提示，确认不出现最终结论。

## R4. 图片识别错但没有标记不确定
- 现象：视觉模型把手写公式认错（如把 ε 认成 e、漏看负号），却以肯定语气批改。
- 影响：批改结论错误，且学生无从察觉。
- 规避：
  - 已实现：发图时提示“看不清必须说明不确定位置，不能假装识别准确”。
  - 待补：按 `docs/ai/vision-answer-review-spec.md` 显式产出 `transcribedAnswer` + `uncertainSegments`，让学生先确认转写再批改。
  - 验收：上传一张刻意潦草/局部模糊的图片，确认反馈中出现不确定提示。

## R5. 用户上传超大图片
- 现象：用户上传几十 MB 的高清照片，导致 data URL 过大、请求超时或被供应商拒绝。
- 影响：批改失败或页面卡顿。
- 规避：
  - 已实现：`ExercisePanel` 限制单张 8MB，超限跳过并提示。
  - 待补：上传前客户端压缩/缩放到合理分辨率；对总附件大小也设上限。
  - 验收：上传一张 >8MB 的图片，确认被跳过且有“超过 8MB，已跳过”提示。

## R6. API Key 存储方式引发隐私担忧
- 现象：用户担心填入的第三方 API Key 被上传或泄露。
- 影响：信任问题，影响内测体验。
- 规避：
  - 已实现：Key 仅存浏览器 `localStorage`（键 `ai-math-tutor-settings`），输入框为密码框；不进数据库。
  - 待补：在设置区显著说明“Key 仅保存在本机浏览器，不上传服务器”；日志/错误信息中绝不打印 Key（代码评审时检查）。
  - 验收：检查网络请求与服务端日志，确认 Key 不会被记录到服务端。

## R7. 教材题源未核对导致内容可信度不足
- 现象：题目 `sourceRef` 写着“待核对题源”，学生误以为是教材原题。
- 影响：内容可信度与版权边界风险。
- 规避：
  - 已实现：占位题源统一写“待从教材对应小节录入（原因：未核对具体题号）”，不编造题号。
  - 待补：对照教材回填已核对题源，并在 UI 上区分“教材原题/改编/过渡题”。见 `docs/content/sequence-limit-content-review.md`。
  - 验收：抽查题目，确认未出现伪造的“例 X/习题 X”编号。

## R8. 数学公式转义错误导致前端显示异常
- 现象：JSON 内 LaTeX 反斜杠转义不当（`\varepsilon` vs `\\varepsilon`），或模型返回未转义内容，导致页面显示乱码或 KaTeX 报错。
- 影响：公式显示错乱，影响阅读。
- 规避：
  - 已实现：内容文件中 LaTeX 按 JSON 规则转义；前端统一用 `MathText`（KaTeX）渲染。
  - 待补：`MathText` 对 KaTeX 解析失败做降级（显示原文而非崩溃）；对模型返回文本中的公式同样走该渲染。
  - 验收：构造含复杂公式的反馈，确认渲染正常或安全降级，不白屏。

## R9. 无 Key / 网络失败时的体验
- 现象：未填 Key 或供应商不可达。
- 影响：用户不知发生了什么。
- 规避：
  - 已实现：未填 Key 时明确提示先保存；请求失败时显示“AI 批改暂时不可用：<原因>”。
  - 待补：区分“正常结果”与“降级结果”，必要时提示检查网络/Key。
- 验收：断网或填错 Base URL，确认有清晰错误提示且不崩溃。

| 级别 | 风险 |
| --- | --- |
| 高（直接影响批改正确性/信任） | R3、R4、R6、R7 |
| 中（影响稳定性/可用性） | R1、R2、R5、R8 |
| 低（体验细节） | R9 |
